# 《容斋随笔》校读项目规划与处理原则

## 目标

将 5000言《容斋随笔》整理为与《聊斋志异》故事相同风格的校读材料：保留纯净原文，提供可切换的注音与注释层、共享词典提示、朗读、人工校读、札记、图片附件、JSON 备份和可复现 PDF。

来源总页：<https://rongzhai.5000yan.com/>

## 放置位置

本项目放在 `practice/rongzhai_suibi/`，与 `liaozhai_stories/`、`shiji/` 平级。

理由：

1. 《容斋随笔》是独立著作，不应归入《聊斋志异》。
2. 全书按卷组织，每卷包含多篇短札；它的层级与单篇故事集合不同。
3. 阅读工具可以共用，但原始资料、目录、校读记录和导出物应保持独立。

## 三层文本策略

5000言的篇章页提供三类内容，必须分开保存：

- `original.txt`：只保存原文，作为清稿和朗读的权威文本。
- `source_notes.tsv`：保存网页注释 JSON 中的词语、释义、键值和次序。
- `translation.txt`：保存现代汉语译文，仅供参考，不混入清稿。

另外生成 `reading.txt`，在原文中加入首次出现的来源脚注标记，并在末尾附脚注。编辑器读取此文件；切换到清稿时会隐藏脚注标记与脚注区，因此朗读和复制清稿仍以纯原文为准。

## 来源与人工内容的边界

- 站点注释标记为 `source_note`，视为来源材料，不冒充本项目的人工判断。
- `review_notes.tsv` 专门记录待核问题。
- 编辑器中新增的注音、行间注、脚注、按语、图片和札记属于人工校读层。
- `source.json` 保存抓取时间、URL、网页编号、篇名、卷次和来源摘要，便于追溯。
- 网页原文中的异文、明显缺字或注释错位不自动改写；先进入待核流程。

## 词典策略

1. 每篇 `reading_terms.csv` 先收录该页的来源注释。
2. 项目共享词典继续从 `practice/project_dictionary/dictionary.csv` 读取匹配项。
3. 来源注释未给拼音时保持空值，不能凭程序臆造。
4. 人工确认后的拼音可写回本篇词表，并在适合时提升到共享词典。
5. 重叠词条按长词优先；来源脚注只标首次出现，避免页面过密。

## 编辑器和 PDF

- 编辑器复用当前 Liaozhai/Shiji 的共享校读界面。
- 每篇使用独立 `storage_key`，防止浏览器存档串篇。
- PDF 必须从最终 `editor.html` 打印，而不是从纯文本重新排版，以保留插图、注音、按语和脚注。
- PDF 导出前将浏览器媒体存储中的图片静态嵌入打印副本，避免异步加载造成漏图。
- 批量 PDF 只在对应编辑器已经生成后执行。

## 导航与批处理

`catalog.csv` 是抓取、构建、导航和进度统计的唯一目录来源。后续应在编辑器中加入上一篇/下一篇链接，并支持：

- 按篇抓取或重抓；
- 按卷构建编辑器；
- 按卷生成 PDF；
- 记录 `pending`、`downloaded`、`reviewed`、`published` 等状态。

## 试点范围

先处理卷一前三篇：

1. 欧率更帖
2. 罗处士志
3. 唐《平蛮碑》

试点用于验证网页结构、注释映射、重叠词条、清稿/注释视图、共享词典和 PDF。通过后再抓取全书目录，避免把解析错误复制到三百余篇。

## 已知风险

- 网站可能限流或返回 403；下载器应设置用户代理、超时并保留已下载成果。
- 网页注释 JSON 可能有拆分或错位，例如注释正文被拆成额外键；原始映射必须原样保存。
- 个别生僻字可能缺少本机字体；PDF 视觉检查仍是交付门槛。
- 短篇数量很多，不能手工复制脚本到每个目录；批处理逻辑应集中在项目根目录。
- 站点内容可更新；重抓时不得无提示覆盖人工校读后的编辑器状态。

## 推进顺序

1. 完成并人工检查三篇试点。
2. 抽取全书目录并确认卷次、篇序和 URL。
3. 将通用编辑器代码从单篇《史记》目录迁移到真正的共享模块。
4. 加入卷内上一篇/下一篇导航和卷级索引。
5. 分卷抓取、校读和生成 PDF。
