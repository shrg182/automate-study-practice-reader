# 《翦商》词典难度与专门词库发展规划

## 目的

为《翦商》各章编辑器增加统一的词语难度设置，使读者能够按自身程度控制正文中的词典提示，同时避免把短语、专名、器物名和普通词语混为同一种“难词”。

本规划建议继续采用五级难度，但将“难度”和“词条类别”分成两个维度：

- 难度回答“一个词对一般读者有多难”。
- 类别回答“这个词条是什么，以及它属于哪个专业领域”。

两者不能互相替代。长度也不能单独决定一个词条是词还是短语。

## 基本决定

1. 普通中英文单词或词语使用五级难度。
2. 短语、固定搭配、引文、专名和书名进入相应的专门词库，不自动参与普通词语难度过滤。
3. 青铜器名和古代器物术语进入“青铜器与器物词库”，默认按 Level 5 Specialist 显示。
4. 章节词表优先于项目词典；项目词典优先于自动推断。
5. 自动分类只能提出建议，不能无记录地覆盖人工等级。
6. 编辑器只载入正文实际出现的词条，并按长词优先匹配，避免短词破坏较长词条。

## 五级难度标准

| 等级 | 名称 | 面向读者 | 判定原则 | 示例类型 |
|---|---|---|---|---|
| 1 | Common 常用 | 一般读者 | 当代常用，通常不需提示 | 日常高频词 |
| 2 | Intermediate 进阶 | 中等阅读者 | 书面语或较低频，但可由上下文理解 | 常见历史叙述词 |
| 3 | Advanced 高阶 | 高阶阅读者 | 文言、古义、学术用法或容易误解的词 | 古今义有差异的词 |
| 4 | Rare 生僻 | 专门阅读者 | 生僻字词、罕见古义、古文字或低频异体 | 生僻古词、古文字用法 |
| 5 | Specialist 专业 | 领域学习者 | 必须依靠考古、历史、礼制、文字学等专业知识 | 青铜器名、考古学术语、祭祀制度术语 |

等级表达的是最低阅读支持需求，不是词语价值、年代或字数。一个双音词可能是 Level 1，一个单字古义也可能是 Level 4；不能仅按字符数分级。

## 词条类别

建议新增 `unit_type`，至少包含：

| `unit_type` | 含义 | 是否使用普通五级过滤 |
|---|---|---|
| `word` | 可独立使用的普通单词或汉语词语 | 是 |
| `classical_word` | 文言词、单字古义或古汉语词 | 是 |
| `specialist_term` | 专业术语，包括多数器物名 | 是，通常为 Level 5 |
| `phrase` | 一般短语或固定搭配 | 否，进入短语词库 |
| `idiom` | 成语、习语、典故性表达 | 否，进入短语或典故词库 |
| `proper_name` | 人名、地名、族名、国名 | 否，进入专名词库 |
| `title` | 书名、篇名、器铭标题 | 否，进入文献题名词库 |
| `quotation` | 引文或较长文句 | 否，进入引文词库 |

短语不能简单定义为“两个字以上”。例如“青铜器”是一个词，“第一章新石器时代的社会升级”则不是词。中英文均应根据语法功能和词汇化程度判断。

## 专门词库

建议在项目词典内保留统一索引，但按领域提供独立视图：

```text
project_dictionary/
├── dictionary.csv                 # 普通词语与统一索引
├── phrases_zh.csv                 # 中文短语、固定搭配、典故
├── phrases_en.csv                 # 英文短语与搭配
├── proper_names.csv               # 人名、地名、族名、国名
└── domains/
    ├── bronze_vessels.csv         # 青铜器、车马器、兵器等
    ├── archaeology.csv            # 考古学、年代学、遗址术语
    ├── ritual_and_sacrifice.csv   # 礼制、祭祀、人牲人祭
    └── paleography.csv            # 甲骨文、金文和古文字
```

第一阶段不必立即拆分物理文件。可以先在现有 CSV 增加字段并由构建脚本生成不同视图；数据稳定后再决定是否拆分源文件。

## 青铜器名称的处理

多数青铜器名适合默认设为 Level 5，因为一般读者即使认识字，也未必知道器形、用途、时代和礼制含义。例如簋、甗、盉、觚等。

建议规则：

- `domain=bronze_vessel` 或现有 `type=bronze_item` 时，默认 `unit_type=specialist_term`、`difficulty=5`。
- 兵器、车马器和青铜构件也可默认 Level 5，但用不同 `domain` 区分。
- “鼎”等已经进入现代常用语的字，在普通义项中可有较低等级；作为具体器类时仍可保留 Level 5。必须支持同形词的不同义项。
- 复合器名、器铭名和带时代/出土地限定的名称可进入器物词库，不应因为字数较多而自动降为普通短语。
- 每个器物词条宜增加器类、用途、时代、形制和参考来源字段，而不仅是一句简注。

## 建议数据模型

现有 `difficulty` 字段保留，并逐步增加：

```csv
term,language,pinyin,unit_type,domain,difficulty,definition,example,difficulty_basis,review_status,sources
簋,zh,guǐ,specialist_term,bronze_vessel,5,古代盛食器,,bronze_item_default,reviewed,...
夯土,zh,hāng tǔ,specialist_term,archaeology,4,分层夯筑的土体,,manual,reviewed,...
从容,zh,cóng róng,word,general,2,不慌不忙,,manual,reviewed,...
```

字段说明：

- `difficulty_basis`：`explicit`、`manual`、`type_default`、`frequency_suggestion` 或 `legacy_migration`。
- `review_status`：`suggested`、`reviewed`、`disputed` 或 `deprecated`。
- `domain`：允许一个词条进入专业视图，同时仍由统一索引搜索。
- `sense_id`：第二阶段可增加，用于处理“鼎”等同形多义词。
- `is_phrase` 不建议与 `unit_type` 并存，避免两个字段发生冲突。

## 等级来源与优先顺序

同一词条可能来自章节词表、项目词典和领域词库。合并时建议使用以下优先顺序：

1. 当前章节经人工确认的显式 `difficulty`。
2. 项目词典中 `review_status=reviewed` 的显式等级。
3. 领域词库的默认等级，例如 `bronze_item → 5`。
4. 来源 `type` 的兼容映射。
5. 自动频率或字符信息给出的建议等级。

较高等级不应总是自动覆盖较低等级。若两个来源冲突，应保存来源和冲突状态，等待人工确认。

## 《翦商》编辑器中的控制

在词典按钮组中增加以下控件：

- `词典提示：开/关`
- `词语难度`下拉菜单：`全部`、`2+`、`3+`、`4+`、`5 专业`
- `词库`下拉菜单：普通词语、青铜器、考古、礼制祭祀、古文字、专名、短语
- `项目词典`链接

建议默认值为 `3+ Advanced`，并保存在浏览器中。难度选项采用“最低显示等级”：选择 `4+` 时显示 Level 4 和 Level 5。

正文提示建议：

- 普通词语使用浅色点线。
- Level 5 专业术语使用不同但克制的标记，并显示领域图标或简短标签。
- 短语和专名默认不批量标记，避免长篇正文出现过多颜色；可通过词库选择显式开启。
- 点击词条后在侧栏显示词典、等级、领域、来源和编辑入口。
- 注音稿仍为只读；难度筛选只改变提示显示，不改写清稿内容。

## 项目词典与章节词表的关系

《翦商》应继续保留章节 `reading_terms.csv`，因为章节注释往往依赖具体语境。项目词典提供跨书共享的通用定义和等级，青铜器词库提供专业定义。

合并显示时：

- 同一词条优先显示章节释义。
- 同时保留项目词典来源，允许查看通用释义。
- 章节中新增或修订的词条先写入本章词表，经过复核后再提升到项目词典。
- 浏览器中的临时编辑仍使用本地覆盖层，不直接改写 CSV。

## 迁移现有数据

1. 为所有 `reading_terms.csv` 增加可选的 `difficulty`、`unit_type` 和 `domain` 列。
2. 将 `rare_word` 初始映射为 Level 4，但标记为 `legacy_migration`，等待复核。
3. 将 `bronze_item` 初始映射为 `specialist_term / bronze_vessel / Level 5`。
4. 识别明显的人名、地名和书名，移入专名视图；不依据长度自动迁移。
5. 对现有项目词典进行冲突报告，列出同词不同等级、同形不同义和缺少拼音的条目。
6. 在人工复核完成前保留原始字段，确保构建结果可回溯。

## 构建与验证要求

构建脚本应验证：

- `difficulty` 只能是 1–5 或空值。
- 参与普通难度过滤的词条必须有允许的 `unit_type`。
- `specialist_term` 必须有 `domain`。
- `phrase`、`proper_name`、`title` 和 `quotation` 不得因旧类型规则自动获得普通词语等级。
- 同语言、同词、同义项的重复记录必须合并并保存全部来源。
- 较长词条优先匹配；DOM 中已有注音、按语和脚注区域不得重复标记。
- PDF 输出不受屏幕难度选择影响，除非用户明确选择“打印词典提示”。

建议增加测试：

- 青铜器名默认进入 Level 5。
- “鼎”的普通义和器类义可以分别存在。
- 中文和英文短语进入各自词库，不参加普通词语等级筛选。
- 章节显式等级优先于项目默认值。
- `3+` 正确显示 Level 3、4、5，并隐藏 Level 1、2。
- 关闭某一领域词库不会删除或改写正文。

## 实施阶段

### 第一阶段：数据规范

确定 `unit_type`、`domain`、`difficulty_basis` 和 `review_status`，更新项目词典构建器和测试。生成迁移报告，但不自动覆盖人工数据。

### 第二阶段：《翦商》试点

选择第一章和青铜器词条最集中的第四章：

- 第一章验证普通词语、考古术语和项目词典合并。
- 第四章验证青铜器名默认 Level 5、同形多义和领域筛选。

### 第三阶段：编辑器控制

在共享 header 的词典组加入开关、最低等级和词库选择器；在侧栏加入词条详情及来源。先只应用于试点章节。

### 第四阶段：全书迁移

人工检查试点后，重建《翦商》全部章节，生成按等级、领域和未复核状态统计的质量报告。

### 第五阶段：短语词库

根据实际积累量决定是否把中英文短语拆为独立文件。没有足够稳定数据前，不应只为目录整齐而提前拆分。

## 暂不实施的事项

- 不按字数自动判定词或短语。
- 不用词频单独决定最终等级。
- 不把所有项目词典匹配项默认高亮。
- 不让浏览器临时修改直接覆盖源 CSV。
- 不在本阶段调整手机端工具栏布局。

## 建议的下一步

先实现数据规范和迁移报告，再以第一章、第四章做双章节试点。试点应由人工检查词条类别和等级；确认五级标准、青铜器默认规则与正文提示密度后，再扩展到全书。
