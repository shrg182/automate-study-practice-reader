# Jianshang Study Materials

This directory contains the working files for generating chapter-by-chapter
reading practice materials for Li Shuo's 《翦商》.

The generated study materials are intended for personal reading practice. Each
chapter can produce:

- a cleaned chapter text;
- a focused reading-term dictionary;
- a generated `shengzibiao` table with pinyin and short annotations;
- an annotated PDF with inline pinyin, source notes, review tables, and page
  references.

Use the web text as the working source because it is easier to split and edit.
Use the PDF as the canonical visual reference for page ranges, captions, image
locations, footnotes, and uncertain OCR passages. The PDF is scanned or
image-heavy, so OCR should be treated as a verification tool rather than as the
primary source.

### Hexagram References

https://en.wikipedia.org/wiki/I_Ching
https://motheringchange.com/hexagrams/

Local working reference:

```text
sources/hexagram_reference.tsv
```

Use this table when OCR turns 周易卦象 diagrams into ordinary text, Latin
letters, boxes, or random symbols. The Mothering Change reference is helpful
because it confirms that each hexagram is composed of two trigrams. In this
project, represent six-line hexagrams as `上卦/下卦` trigram pairs, such as
`☵/☳`, when single Unicode hexagram characters do not render reliably in the
generated PDF.

Recommended review order:

1. If the nearby text gives a卦名, look it up in
   `sources/hexagram_reference.tsv`.
2. If the nearby text gives 上下卦, match those trigrams directly.
3. If OCR captured only the visual diagram and no reliable name or 上下卦,
   compare against the source PDF or reference chart manually before editing.

File roles:

- `sources/chapter_map.csv`: maps chapter IDs to source PDF pages and printed
  book pages.
- `CHAPTER_README_TEMPLATE.md`: reusable chapter README format for processing,
  editing, review, regeneration logs, and quality checks.
- `source.txt`: chapter text split from `sources/136.txt`.
- `chapter_XX_clean.txt`: reviewed text used for generation.
- `editor.html`: browser workspace for manual edition against source PDF page
  images; generated by `build_ocr_editor.py`.
- `reference_tables.html`: searchable, book-wide vocabulary and bronze-item
  reference page aggregated from the current chapter CSV dictionaries; rebuilt
  automatically by `build_ocr_editor.py`.
- `shared/editor_header.js`: shared HTML5 Web Component that supplies the
  chapter editors' common header, navigation links, and editing controls.
- `shared/editor_toc.js`: generated Web Component containing the shared chapter
  table of contents and work instructions; its chapter data comes from
  `sources/chapter_map.csv`.
- `chapter_XX_clean_edited.txt`: manual-edition export seeded from
  `chapter_XX_clean.txt`; promote back to `chapter_XX_clean.txt` only after
  review.
- `chapter_XX_edit_log.txt`: exported editor notes and history metadata.
- `reading_terms.csv`: curated pinyin and annotation dictionary for the chapter.
- `oracle_review.tsv`: optional manual-review table for difficult ancient text,
  oracle-bone text, bronze inscriptions, damaged diagrams, and OCR-resistant
  passages.
- `chapter_XX_shengzibiao.txt`: generated reading-term table.
- `chapter_XX_annotated.pdf`: generated annotated reading PDF.

## Standard Workflow

Run commands from:

```bash
cd practice/jianshang
```

### 0. Build Manual OCR Editor

Generate a browser editor for one chapter:

```bash
python3 build_ocr_editor.py --chapter chapter_01 --extract-pages
```

The editor shows source PDF page images from `翦商.pdf` beside editable text
seeded from the processed `chapter_XX_clean.txt`. Browser downloads should be
treated as the manual edition: `chapter_XX_clean_edited.txt` and
`chapter_XX_edit_log.txt`.

Editor version 4 uses a rich-text surface for every source page while retaining
the side-by-side scan and page-number mapping. Its Preview-style formatting
menu provides five highlight colors, underline, and strikethrough, with a
separate bold button. Formatting is saved independently from the clean text,
so TXT export and downstream PDF generation are not polluted by HTML markup.

Other features include reversible clean/annotated viewing, one-click use of
the chapter reading-term table, manual pinyin notes, footnotes, commentary and
doubt markers, browser read-aloud with voice and speed controls, local
autosave, TXT/log export, and JSON backup/import. Version-4 JSON backups contain
both `texts` and per-page rich `html`; older backups containing only `texts`
remain importable and are promoted automatically. The annotated view is a
read-only projection; switching back restores the editable rich clean text,
and TXT exports always use that clean source plus any annotations inserted
manually.

Original book footnotes retain the `[[fn:n]]` marker and `〔注n〕` label.
Footnotes added in the browser editor use the separate `[[editor-fn:n]]`
marker and `〔编者注n〕` label, with their own numbering sequence.

Rebuild every mapped chapter editor after changing the generator:

```bash
python3 build_ocr_editor.py --all
```

Each chapter editor includes **全书总词表** and **青铜器名总表** buttons. They
open the corresponding section of `reference_tables.html` in a new tab. At the
current stage this page is generated from all chapter `reading_terms.csv` and
`bronze_terms.csv` files and records the contributing chapter IDs.

### 1. Split a Chapter

```bash
python3 jianshang_tools.py split \
  --source sources/136.txt \
  --chapter chapter_XX \
  --output chapter_XX/source.txt
```

Copy `source.txt` to `chapter_XX_clean.txt`, then manually review the clean
file before generating outputs.

Use `CHAPTER_README_TEMPLATE.md` when creating or professionalizing a chapter
README. The template is designed to preserve source mapping, generation
commands, confirmed corrections, unresolved manual-review items, ancient-text
review rows, footnote status, and regeneration history in one consistent place.

### 2. Review and Clean Text

For each `chapter_XX_clean.txt`:

- normalize punctuation and line breaks;
- verify suspicious web-text or OCR passages against the PDF;
- add `（图）` to image captions or image-placeholder lines;
- repair captions that split prose sentences;
- preserve square placeholders `□` where the original source has unreadable or
  untranscribed characters;
- avoid guessing oracle-bone, bronze-inscription, or classical text when the
  source is uncertain.

Use inline review notes when uncertainty belongs in the reading text:

```text
〔待核：此处甲骨文字形未能可靠辨识，需人工校读。〕
〔校疑：网页作“瞿”，据PDF疑为“斝”。〕
```

Use `oracle_review.tsv` when the passage is better handled in a separate manual
review table.

### 3. Check Image Caption Flow

```bash
python3 jianshang_tools.py lint-images chapter_XX/chapter_XX_clean.txt
```

This check catches captions that interrupt a sentence. A clean result should
report no caption-flow warnings.

### 4. Generate the Shengzibiao

```bash
python3 jianshang_tools.py table \
  chapter_XX/chapter_XX_clean.txt \
  --dictionary chapter_XX/reading_terms.csv \
  -o chapter_XX/chapter_XX_shengzibiao.txt \
  --max-terms-percent 0.02 \
  --min-terms 20
```

The table includes the term, pinyin, type, annotation, occurrence count, and a
source example.

### 5. Generate the Annotated PDF

Without an ancient-text review table:

```bash
python3 jianshang_tools.py pdf \
  chapter_XX/chapter_XX_clean.txt \
  --dictionary chapter_XX/reading_terms.csv \
  --bronze-dictionary chapter_04/bronze_terms.csv \
  -o chapter_XX/chapter_XX_annotated.pdf \
  --title '《翦商》第XX章注音阅读版' \
  --chapter-map sources/chapter_map.csv
```

With an ancient-text review table:

```bash
python3 jianshang_tools.py pdf \
  chapter_XX/chapter_XX_clean.txt \
  --dictionary chapter_XX/reading_terms.csv \
  --bronze-dictionary chapter_04/bronze_terms.csv \
  --ancient-review chapter_XX/oracle_review.tsv \
  -o chapter_XX/chapter_XX_annotated.pdf \
  --title '《翦商》第XX章注音阅读版' \
  --chapter-map sources/chapter_map.csv
```

### 6. Run Structural Checks

```bash
python3 jianshang_tools.py check-pdf chapter_XX/chapter_XX_clean.txt
```

When checking against source PDF pages:

```bash
python3 jianshang_tools.py check-pdf \
  chapter_XX/chapter_XX_clean.txt \
  --pdf 翦商.pdf \
  --start-page START_PAGE \
  --end-page END_PAGE
```

The check covers:

- footnote marker consistency when explicit markers are present;
- image-caption flow;
- suspicious OCR-like tokens;
- optional OCR caption comparison against PDF pages.

## Reading-Term Dictionary Standards

### Project-wide master tables

The project will maintain two shared, book-wide tables:

- one master vocabulary table covering vocabulary from every chapter;
- one master bronze-item-name table covering bronze vessels, weapons, fittings,
  and related object names from every chapter.

These master tables are the project-wide reference and should deduplicate the
same term across chapters while recording every chapter in which it is used.
Chapter-level `reading_terms.csv` and `bronze_terms.csv` files are working
subsets for chapter generation and review, not separate competing dictionaries.
When a chapter introduces or corrects a term, update both its chapter subset and
the applicable master table. A chapter editor may display a filtered view, but
the complete tables must remain available for cross-chapter review.

Both master tables should retain at least `term`, `pinyin`, `type`,
`annotation`, and a chapter/source field. Bronze-item names remain in the
bronze master table even if they also appear in the general vocabulary table.

`reading_terms.csv` uses:

```csv
term,pinyin,type,annotation
```

Recommended `type` values:

- `rare_word`: uncommon character, classical word, or difficult written form.
- `person`: personal name.
- `place`: geographic name.
- `site_or_culture`: archaeological site or culture.
- `artifact`: artifact or material object.
- `bronze_item`: bronze vessel, weapon, or related object.
- `concept`: historical, political, ritual, or archaeological concept.
- `text`: book, chapter, classic, inscription, or transmitted document.
- `added`: manually retained term that should survive generation caps.

Selection guidelines:

- prioritize terms that block comprehension;
- include recurring people, places, sites, artifacts, texts, and concepts;
- keep annotations short and reader-facing;
- avoid annotating ordinary vocabulary unless it is central to the chapter;
- mark pronunciation decisions in the annotation when a term has multiple
  readings.

Example:

```csv
召公奭,shào gōng shì,person,周初重臣，燕国始封祖。
鬲,lì,rare_word,古代炊器，常见于考古材料。
人牲,rén shēng,concept,被杀用于祭祀的人。
```

Global pronunciation or OCR conventions can be recorded in:

```text
sources/confusing_terms.tsv
```

## Ancient Text Review Tables

Use `oracle_review.tsv` for passages that should not be silently guessed:

```tsv
source	current_text	issue	action
《合集》2631	〔待核〕	甲骨文字形未能可靠辨识。	需人工校读。
```

This table is useful for:

- oracle-bone transcriptions;
- bronze inscriptions;
- damaged or hard-to-OCR ancient characters;
- line diagrams or hexagram symbols that OCR turns into random text;
- classical quotations with rare or variant characters.

When supplied with `--ancient-review`, the generated PDF places a
“疑难甲骨文字词校读表” after the bronze-item table.

## Image Captions

Image captions and image placeholders should end with `（图）`.

If an image caption splits a prose sentence, move the caption after the complete
sentence or merge the split sentence around it. The final structure should keep
the reading flow intact while preserving the image location.

Example:

```text
这一发现说明……

某遗址平面图（图）

下一段正文……
```

## Footnotes

The source `注释` section is preserved in the generated PDF when present.

Rules:

- avoid treating ordinary numbers as footnotes;
- keep numbers before units or classifiers inline, such as `30字`, `20只`,
  `3号`, and `13枚`;
- use explicit markers such as `[[fn:20]]` only after verifying that the source
  PDF has a true superscript footnote marker;
- split clustered source notes when the web text merges several notes into one.

## Quality Checklist

Before treating a chapter as complete, confirm:

- `chapter_XX_clean.txt` has no website metadata or page headers;
- subtitles are flush-left in the generated PDF;
- image captions end with `（图）`;
- captions do not interrupt prose sentences;
- uncertain ancient text is marked inline or listed in `oracle_review.tsv`;
- `reading_terms.csv` is focused and not overgrown;
- `chapter_map.csv` has correct PDF and printed page ranges;
- the annotated PDF source note shows the chapter-specific printed-page range
  derived from `chapter_map.csv`, not a copied or hard-coded range;
- `shengzibiao` and PDF regenerate without errors;
- `check-pdf` reports no unresolved caption-flow or suspicious OCR warnings.

## Limitations

This is a semi-automatic workflow. The web text is cleaner than OCR, but it can
still contain conversion errors, missing captions, merged notes, damaged
punctuation, and OCR-like substitutions.

### Page-numbering system and deferred editor fine-tuning

The page labels currently shown as `PDF` in generated editors are consistently
two greater than the physical pages extracted from `翦商.pdf`. For example,
Chapter 7 displays `PDF 131` while loading physical source page
`pdf_pages/page-129.jpg`; both correspond to printed book page `117`.

This offset is project-wide in `sources/chapter_map.csv`:

- `pdf_page_start/end` (currently displayed by the editor) = physical source-PDF page + `2`;
- `source_page_start/end` = the physical page index used by `pdftoppm` and the page-image filenames;
- `printed_page_start/end` = the number printed on the scanned book page and is currently correct.

Generated annotated PDFs now display three distinct page numbers in the footer:

- `annotated PDF page`: the page number in the generated annotated reading PDF;
- `source PDF page`: the physical page index in the original `翦商.pdf` file,
  matching `source_page_start/end` and the extracted page-image filename;
- `printed page`: the page number printed on the scanned book page.

The annotated-PDF number is output-dependent and may not have a one-to-one
relationship with a source page because reflow, vocabulary tables, and source
notes can change pagination. It should therefore never be presented as another
name for the source-PDF number.

The Chapter 9 editor now also distinguishes `PDF 阅读器页`, `源 PDF 页`, and
`印刷页`. Retrofitting this clearer editor display across earlier chapters and
reviewing the labels remain final fine-tuning tasks. At that point:

1. Use explicit, non-overlapping labels for annotated PDF, source PDF, and
   printed book pages.
2. Make editor headers, navigation buttons, page headings, TXT export headers,
   backups, and edit-log page references use the chosen numbering consistently.
3. Define how source-page references map into the reflowed annotated PDF,
   including pages that span more than one annotated-output page.
4. Rebuild every existing editor and verify that saved manual exports/backups
   remain importable or receive a safe page-label migration.
5. Recheck the introduction and Chapters 1-27; the audited offset is uniformly
   `+2` across all 28 mapped ranges.

Common risk areas:

- dense source notes;
- image captions and diagrams;
- bronze vessel names;
- oracle-bone text and square placeholders;
- bronze inscriptions;
- rare or variant classical characters;
- mixed Chinese, Latin letters, and archaeological IDs.

For uncertain ancient text, prefer transparent review notes and `oracle_review.tsv`
over confident but unsupported correction.
